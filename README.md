# Hestia

本地开发服务启动管理器的 macOS 桌面端。界面按 Claude Design 项目「Mac应用启动管理器」中的
`Hestia 液态玻璃.dc.html` 实现，进程托管由 Rust 侧真实执行。

## 运行

```bash
pnpm install
pnpm tauri dev
```

打包：

```bash
pnpm tauri build
```

测试（进程托管的集成测试会真的拉起进程再回收）：

```bash
cd src-tauri && cargo test
```

`pnpm dev` 只启前端，没有后端可调，界面会停在空状态，仅适合改样式。

## 进程托管

服务配置持久化在 `~/Library/Application Support/com.kira.hestia/config.json`。
首次运行不写入任何示例服务——示例里的路径指向本机不存在的目录，装到别人机器上会一开
就是一片「工作目录不存在」。配置为空时仪表盘显示一张可点击的引导卡片，
点进去就是新建表单。`tests/process.rs` 的 `first_run_starts_with_no_services` 守着这条。

- **启动**：用登录 shell（`$SHELL -lc`）执行启动命令，`pre_exec` 里调 `setsid`
  建立独立会话，因此停止时能把整棵进程树一起收掉。工作目录支持 `~`，环境变量逐条注入。
- **停止**：配了停止命令就先执行它并等 8 秒；没配或没生效则向进程组发 `SIGTERM`，
  再等 5 秒仍在就发 `SIGKILL`。
- **日志**：`stdout` 与 `stderr` 各起一个线程按行读取，按行内容判定 INFO / WARN / ERROR，
  内存环形缓冲 4000 行，每 200ms 成批推给前端，避免话痨进程刷爆 IPC。
- **崩溃与重启**：非手动退出记为异常并累计错误数；开启自动重启后按 1、2、4、8、16 秒
  退避重试，最多 5 次。
- **资源采样**：`sysinfo` 每 1.4 秒刷新一次，按父子关系累加整棵进程树的 CPU 与常驻内存。
- **CPU 口径**：`sysinfo` 给的是「占单核的百分比」，Hestia 再按进程树累加，
  因此多进程 / 多线程时超过 100% 是正常的——单个忙循环读到 101%，四个并行读到 404%，
  与 `top`、活动监视器同一口径。界面上的占比条、颜色阈值、健康分都按整机容量折算
  （`Snapshot.cores` 上报逻辑核心数），仪表盘的「总 CPU 占用」直接显示占整机的百分比。
  另外主窗口与菜单栏窗口各有一个轮询，两者撞在一起时 CPU 差值的间隔会过短，
  实测紧邻 50ms 再采一次会读到 4%（真实值 101%），因此刷新间隔不足 400ms 时不重新
  刷新 sysinfo，沿用上一次的 CPU 与内存；状态、端口、错误这些不依赖刷新的字段照常重算。
- **端口推断**：不少工具在配置端口被占用时会自动改用别的端口，只看配置值会对不上。
  因此用 `lsof` 按进程树的 pid 查实际监听的端口。lsof 单次约 46ms，按节拍每拍都跑偏重，
  而端口起来后不会变，所以按「服务 id + 启动代次」缓存：进程刚起来还没绑端口时逐拍轮询，
  一旦探到就不再查，超过 60 秒仍无结果则认定它不监听端口。稳态下一次都不查，
  采样耗时维持在 8ms 左右（`tests/bench_snapshot.rs` 有回归约束）。
  界面上端口一律显示实际探测值，与配置值不一致时标黄并在悬停时说明。
- **排序**：侧栏的服务列表支持拖拽排序，落盘时按新顺序重写 `config.json` 的 `services`。
  后端的 `reorder_services` 对没在 ids 里出现的服务保持原有相对次序并排在后面，
  因此前端拿的是旧列表时也不会丢掉新增的服务。
  交互没有用 HTML5 的 `draggable`——WKWebView 里从 `<button>` 这类表单控件发起原生拖拽
  不可靠，实测松手后顺序不变。改为 pointer 事件，移动与松手监听挂在 window 上，
  指针移出列表范围也不会丢事件；位移不足 4px 视为点击，仍然打开详情页。
- **退出与强杀**：正常退出时向所有被托管的进程组发信号。但那条路覆盖不了信号终止，
  因此另做两层兜底——`reaper.rs` 为 SIGTERM / SIGINT / SIGHUP 装处理函数就地回收
  （处理函数里只读一组原子量并调 `kill`，两者都是异步信号安全的）；运行中的进程组
  同时落盘到 `running.json`，下次启动先用 `ps` 比对命令行确认还是同一个进程
  （pid 可能已被复用），再整组回收。SIGKILL（强制退出）只能靠后面这层。

## 图标

- **应用图标**：`src-tauri/icons/source-original.png` 是原始画稿，
  `source.png` 是据此生成的 1024×1024 制版稿——按实测的 210/1254 圆角比例做透明蒙版，
  再按 macOS 惯例把画面缩到 824 居中、四周留透明边，这样在 Dock 里才和其它应用一样大。
  各尺寸由 `pnpm tauri icon src-tauri/icons/source.png` 生成（生成出的 ios/ 与 android/
  目录本项目用不到，已删除）。
- **菜单栏图标**：`icons/tray-source.png` 是设计稿原图，上排两张大图、下排五帧动画。
  `icons/make_tray.py` 从中裁出 `tray-idle.png`（取上排静态态）与 `tray-run-1..5.png`
  （取下排五帧），输出 34×36 像素，即 18 点高 @2x。
  两处关键处理：其一，尺度与位置都按「机身像素」归一（机身指排除橙黄尾焰后的部分），
  先按机身面积的平方根折算尺度、再按机身质心做亚像素平移——原稿五帧之间本身有约 4% 的
  尺寸差，直接用会让机身随尾焰一起晃；处理后五帧的机身质心漂移为 0.06 像素。
  其二，内容裁到贴边不留透明边距：`tray-icon` 把图标按 18 点高渲染
  （见其 `platform_impl/macos/mod.rs` 里写死的 `icon_height: f64 = 18.0`），
  整张图的高度都算进这 18 点，留白等于白白缩小可见面积。
  彩色图不能走 template 模式（`icon_as_template(false)`）——那只取 alpha 渲染成单色剪影，
  颜色会全部丢失。代价是不随系统深浅色反色，蓝白配色在深浅菜单栏下都看得清。

## 菜单栏

托盘图标按运行状态切换：有服务在跑时循环播放五帧尾焰（每帧 170ms），
全部停止时换成熄火的静止帧。帧在启动时一次性解码，图标没变化就不下发。
无服务运行时轮询降到 500ms 一次。

- 左键点击：在图标正下方开合菜单栏面板，面板是独立的透明窗口，加载
  `index.html#menubar`，高度按服务数量自适应，点击别处自动收起，外观跟随系统。
- 右键点击：显示主窗口 / 全部启动 / 全部停止 / 退出。
- 关闭主窗口只是隐藏，进程继续托管；真正退出走托盘菜单的「退出 Hestia」。

面板的「点击别处即收起」（`src/dismiss.rs`）绕了两个坑，都是实测出来的：

1. **不能靠 `WindowEvent::Focused(false)`。** 点状态栏图标展开面板时，事件日志里只有
   `Moved`、`可见=true`，从头到尾没有 `Focused(true)`——面板从未成为 key window，
   自然也永远不会失焦。成因是点状态栏图标不激活应用，而新版 macOS 限制后台应用的
   程序化激活，`tao` 的 `set_focus` 里那句 `activateIgnoringOtherApps:` 不再生效。
   改用 AppKit 的全局鼠标事件监视器（`addGlobalMonitorForEventsMatchingMask`），
   鼠标事件的全局监视不需要辅助功能授权，只有键盘事件需要。
2. **托盘图标自身的点击也会进全局监视器**，并不是只捕获「其它应用」的事件。
   于是按下时监视器把面板关掉、抬起时 `toggle_menubar` 又开一次；双屏下两块屏幕的
   事件时序不同，就表现成「点开立刻收起」。按「展开后豁免固定时长」挡不住，因为
   按下发生在展开之前。现在改看托盘事件的时间戳：光标划过图标时 tray-icon 会持续派发
   Enter / Move，点击必然在这些事件之后，所以最近 400ms 内有任何托盘事件就跳过收起；
   光标移开后不再有事件，静默期自动失效。`dismiss.rs` 的单元测试守着这个判断方向。

## 与设计稿的差异

1. **窗口信号灯**：设计稿在顶栏左侧画了三个 12px 圆点模拟 macOS 红黄绿按钮。桌面端改用系统原生按钮
   （`titleBarStyle: "Transparent"` + `hiddenTitle: true`），顶栏左侧预留 82px 让位，整条顶栏设为
   `data-tauri-drag-region` 拖拽区。
2. **重复浮层**：设计稿模板里菜单栏面板和新手引导各写了两遍。其中新手引导的第一组绑定
   `tour.path`、`tour.title` 等字段，而逻辑层导出的是 `tourPath`、`tourTitle`，渲染出来是空的。
   本实现各只渲染一次，采用字段能对上的那一组。
3. **写死的展示数据改为真实推导**：日志保留设置在设计稿里是固定字符串，现在由缓冲用量推导。
4. **监控面板改成两套布局，并与仪表盘拉开分工**：设计稿按 1440 宽绘制，表格用固定列宽、
   九列合计 1254，而窗口最小 1100、内容区只有约 820，横向滚动条会一直挂着。现在按容器
   实测宽度切换——够宽仍是一行一条的表格，不够则拆成分行卡片（身份 / 资源 / 其余指标三行）。
   另外原设计里监控和仪表盘有五个字段重复（名称、状态、端口、运行时长、重启次数），
   看起来像两个同样的列表。现在监控去掉运行时长与重启次数（仪表盘的服务卡片已有），
   换成只有持续采样才拿得到的量：CPU 与内存的窗口峰值（40 点 × 1.4 秒 ≈ 56 秒）、
   累计错误条数，趋势曲线的高度从 26 提到 40、列宽在 1440 下从约 70 提到约 238。
   仪表盘那边不动，继续负责命令、目录与启停。
5. **删掉「最近告警」**：设计稿在监控面板底部有一块告警区。实现时把它改成了从日志流里
   取最近的 ERROR / WARN 行，但日志级别是按行内容里的关键词判定的（含 error / warn 就算），
   构建工具的正常输出经常被误判，误报率高到没有参考价值，因此整块移除。
6. **新增删除入口**：设计稿没有删除服务的按钮。配置变成可持久化的之后没有删除
   就无法收拾，编辑态的头部加了一个「删除」。
7. **删掉工作流**：设计稿有「工作流」页与编排界面，可以把服务按阶段串起来一键拉起。
   实际使用下来没有价值，整块移除——含前端两个页面、`WorkflowConfig` / `WfRun` 结构、
   `run_workflow` / `stop_workflow` 及其阶段就绪探测。旧配置文件里残留的 `workflows`
   字段会被 serde 忽略，下次保存时自然消失。
8. **字体**：设计稿从 Google Fonts 加载 Inter Tight 与 JetBrains Mono，桌面端改用 `@fontsource`
   本地打包，离线可用；中文仍回退到 PingFang SC。
9. **工作目录改为可选取**：设计稿只有一个手输入框。现在旁边加了「选择」按钮，调用系统目录
   对话框（`tauri-plugin-dialog`，只申请 `dialog:allow-open`，不涉及文件读写）。
   选中后写回的是绝对路径，输入框仍可手改成 `~` 开头的写法。
10. **监控面板加了筛选**：顶部一排状态筛选（带计数）、搜索（服务名 / 项目 / 端口）和排序
   （默认 / CPU / 内存 / 名称）。这套筛选状态（`monQ` / `monFilter` / `monSort`）与仪表盘的
   `q` / `filter` 分开存，两个页面互不影响。行与行之间补了一条左右缩进的分隔线——
   行本身是圆角的，直接用 `border-top` 会在两端跟着圆角弯下去，所以用伪元素画。
11. **去掉资源占比条**：数值旁边原本各有一条占比条，两条的分母不一样——CPU 那条是整机
   核数，内存那条却是写死的 1600MB。内存超过 1.6G 就一律顶格，实测 4669M 和 8362M
   画出来完全一致，差 1.8 倍看不出来。数值、峰值和趋势曲线已经把量级说清楚了，整条移除。
12. **菜单栏面板单列底色令牌 `--mbPanel`**：原来复用 `--panelSolid`，但那个令牌是给命令面板
   和新手引导用的，它们压在主窗口 `#070B18` 的页面底色上，深色 0.55 的透明度刚好。
   菜单栏窗口是透明的，背后直接是桌面壁纸，0.55 在浅色壁纸上会被冲成灰蓝，
   和浅色模式的白面板几乎分不出来。现在深色 0.88、浅色 0.92，模式差异才立得住。
13. **应用标识统一换成真正的应用图标**：原来用的是一个通用线条字形（`Brand` 组件 +
   `BRAND_PATH`），现在四处全部改用 `src/assets/app-icon.png`（由
   `src-tauri/icons/source-original.png` 缩到 128×128 得到），和 Dock 里那张一致：
   侧栏左上角 38px、监控面板「Hestia」那一行 26px、菜单栏面板顶部 24px、
   新手引导第一页 54px。图源自带的圆角比容器的小，外层圆角裁一刀只会切掉更多，
   不会露出白角。`Brand` 与 `BRAND_PATH` 至此无人引用，已删除；引导第一页原本复用的就是
   `BRAND_PATH`，改成 `path: ""` 表示这一步用应用图标，由 `overlays/Tour.tsx` 分支处理。
   托盘图标不在此列，仍是像素风火箭。
14. **趋势曲线改为按自身峰值归一**：原来固定拿 100 当满刻度，而 CPU 是「占单核」的口径，
   超过一个核的部分会被 `Math.min` 削平成一条直线，多进程服务的曲线全是顶格。现在按该服务
   窗口内的峰值归一，下限压在 25，免得常年 0.3% 的进程被放大成剧烈起伏；绝对量由旁边的
   「峰值」数字给出。

## 资源占用

以下为 release 构建、8 个服务配置且全部处于已停止状态时的实测值
（`ps -o cputime` 累计时间差，30 秒均值）：

| 状态 | CPU |
|---|---|
| 窗口不在前台 | 0.4% |
| 窗口在前台 | 约 5~7% |

差额几乎全部来自背景光晕的 `drift` 动画。只要有 CSS 动画在跑，WebKit 就会持续合成
整个窗口，与 `filter: blur()`、`backdrop-filter` 都无关——把它们逐一关掉都不降；
降帧率也压不下去（`steps(24)`、约 1.3fps 时仍多耗约 4 个百分点）。
因此 `lib/useAmbientMotion.ts` 在窗口失去焦点时暂停动画，回到前台再恢复，
并尊重系统的「减弱动态效果」设置。

若前台时的 5~7% 仍嫌高，可以把 `.blob` 的动画整体去掉，代价是背景变成静止的渐变。

内存（release，`phys_footprint`）：Rust 主进程约 30MB，WebKit 三个辅助进程合计约
140MB，整体约 170MB。绝大部分是 WKWebView 的固定开销，用 Web 技术做界面就避不开。
debug 构建会显著高于这个数，不要拿 `pnpm tauri dev` 的数字做判断。

进程采样本身很轻：`snapshot` 单次耗时空载 0.1ms、有进程在跑时 8.2ms（debug 构建），
相对 1.4 秒的节拍可以忽略，`tests/bench_snapshot.rs` 对此有回归约束。

## 尚未接线的设置项

「开机自启 Hestia」和「异常时系统通知」两个开关会被持久化，但没有实际效果——
前者需要 `tauri-plugin-autostart` 注册登录项，后者需要 `tauri-plugin-notification`。

## 打包注意

菜单栏面板是透明圆角窗口，因此开启了 `app.macOSPrivateApi`（对应 Cargo 的
`macos-private-api` 特性）。这会用到 macOS 私有 API，自行分发没问题，提交 Mac App Store
会被拒。若要上架，需把该窗口改成不透明并去掉圆角。
